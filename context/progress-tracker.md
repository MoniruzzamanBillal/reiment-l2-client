## Recent Activity

- Spec `22` (bugfix, discovered testing spec `21`): `useAuthStore.ts`'s `logout()` only called
  `Cookies.remove(...)` (client-side `js-cookie`), which can never clear the `httpOnly` `refreshToken` cookie
  spec `17`/`21` introduced — so "logout" left a fully valid refresh token live in the browser. Confirmed via
  Playwright: logged in, navigated to `/dashboard`, clicked Logout (`Sidebar.tsx`) — the `accessToken` cookie
  was correctly gone afterward but `refreshToken` was still present and unchanged; replaying that value
  directly against `POST /auth/refresh-token` returned 200 with a fresh access token, proving the session
  hadn't actually ended server-side. Fixed by having `logout()` also fire
  `axiosInstance.post("/auth/logout", {})` (best-effort, `.catch(() => {})`, kept the function synchronous so
  `Sidebar.tsx`'s call site didn't need to change) against the server's new `POST /auth/logout` route (server
  spec `18`), which clears both cookies via `res.clearCookie`. Re-verified via the same Playwright scenario:
  both cookies now gone from the browser's cookie jar post-logout, and replaying the pre-logout refresh-token
  value now correctly 401s. `yarn build`/`yarn lint` clean at the pre-existing baseline (confirmed no circular-
  import breakage from `useAuthStore.ts` importing `axiosInstance.ts`, which already imports `useAuthStore` for
  the refresh-sync fix above — both references are inside function bodies, not top-level module evaluation, so
  the circular import resolves fine at runtime).
